## Conventions for every MTR workflow

- Settings → **Error workflow** = `MTR – 99 Error Handler`.
- When a Code node throws on purpose, start the message with `deal <id>:` (e.g. `deal 123456789: CCEW note not found`). MTR – 99 turns that into a HubSpot link in the alert and the subject.

## MTR – 05 / 06 network letters

`MTR – 05` watches the three distributor Gmail labels (read-only; the PTC workflows are untouched), picks the approval PDF (Ausgrid: `Notification Letter…`, Endeavour: `…_PTC_…`, Essential: first PDF), has Claude read the NMI and reference, then runs `MTR – 06` once per letter. `MTR – 06` finds the deal by NMI, skips the letter if a file with the same name is already attached (the team may have uploaded it by hand), otherwise uploads it under its original name with a note, sets Network Approval Reference, and, if the deal was on hold only for the letter, clears the hold and re-runs `MTR – 02`.

`MTR – 06` writes to HubSpot whenever it runs (dry run or not). The test harness's `letter` mode sets `testOnly`, which stops before any write.
